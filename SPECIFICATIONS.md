# Neckass Digital Gazette — Feature Specifications

This document describes the current in-repo feature set, reconciled against the
source. Line-number citations were dropped when the files they pointed into
were rewritten; a claim here is checked by reading the element it names, not by
following a line number that has since moved.

## Shape of the site
- **The front page (`index.html`)** is one issue: lead item with deck and
  byline, a briefs column, corrections, weather, classifieds, letters, and a
  colophon. A complete standing issue is present in the markup, so the page
  reads without JavaScript.
- **Issue composition (`modules/issue.js`)** is deterministic. The issue number
  is days elapsed since the first edition (2024-09-29); that number seeds
  selection from `data/formats.js`. `/?issue=YYYY-MM-DD` renders any past
  issue, and `archive.html` lists recent ones.
- **The wire** is the interactive section beneath the front page: one item at a
  time from the curated catalogue (`data/headlines.js`) or the on-device
  generator (`llm.js`, `data/llm-beats.js`), with copy, share, and clipping
  export.
- **URL ownership.** A bare visit does not write `?headline=`. The wire item
  claims the address, title, and share metadata only when the reader shuffles
  or arrives with that parameter, so sharing the homepage shares the issue.

## Page-wide expectations
### Document metadata
- `<html lang="en">` is set, the front-page title is **"Neckass | Digital Gazette"**, and every page carries a non-empty meta description.
- Open Graph tags are provided for title, description, image, and URL in the static HTML head; `og:image` references `og-image.png` (1200×630 PNG, generated by `bun run og:generate`). PNG rather than SVG because no major platform renders SVG link previews.
- `modules/head.js` updates metadata at runtime when a wire item is rendered — `<title>`, `meta[name="description"]`, and the Open Graph title/description/url — and writes or updates the canonical link to match. A bare visit leaves the issue's own metadata in place.
- Every page links the icon set (`/favicon.ico`, `/favicon.svg`, `/apple-touch-icon.png`), the web manifest, and the feed (`/feed.xml`) as `rel="alternate"`.

### Fonts & base theming
- No font request leaves the site. Fraunces is self-hosted as a variable woff2
  (`fonts/fraunces-latin-var.woff2`, `font-display: swap`) and used through
  `--headline-font`; body copy uses the system stack in `--font`.
- CSS root variables define the newsprint palette, radius and shadow; `body` uses the `--bg`/`--text` aliases over `--surface-1`/`--text-primary`. A `prefers-color-scheme: dark` block redefines the tokens.

### Layout grid & spacing
- Content is wrapped in `.page-shell` (max width 1100px) with rounded corners, border, and shadow. The layout uses a single column under 900px and a two-column grid at ≥900px with a sticky command rail. Body padding is 28/24/48 px (responsive adjustments on small screens).

## Masthead (topbar)
- The topbar contains the brand block (“Neckass” and “Digital Gazette”). The row is separated from the hero by a bottom border and margin spacing.

## Masthead line
- `#masthead-date` carries the issue's date and number. It ships with standing
  copy — "Published daily · Department of neckassery" — so the page reads
  correctly before, and without, JavaScript, and is replaced on load with the
  active issue's localized date and `No. N`.
- `#back-issue-notice` is `hidden` on today's issue. When `?issue=YYYY-MM-DD`
  resolves to a past date it is revealed, names the issue being read, and
  offers a link back to today.

## The wire (interactive half, below the issue)
### Structure & labels
- Section heading **“The wire”** (`#wire-title`), with the note **“New items, one at a time. Not part of today’s issue.”**
- Item element: `<h3 id="headline" tabindex="-1" aria-label="Headline">` with initial text “Loading...”.
- Helper line below the headline reads **“Shuffle for a fresh line, then copy or share it instantly.”**

### Controls & loader
- Buttons:
  - **Previous** (`#prev-btn`, aria-label “View Previous Headline”).
  - **Next item** (`#next-btn`, aria-label “Shuffle headline”).
  - On small screens, `#headline-quick-actions` is revealed and its buttons (`#jump-copy`, `#jump-share`, `#jump-export`) scroll to the copy, share and clipping cards and focus their primary control.
- Loader element: `<div id="loader" class="loader" role="status" aria-live="polite" aria-hidden="true">Loading...</div>`. Loader visibility is toggled via the `.is-visible` class and `aria-hidden` state updates during transitions.

### Headline behavior
- Headlines are randomly selected from the curated `headlines` array; additional generated headlines can be appended when the tiny LLM helper succeeds. Next/Shuffle asks the on-device generator first when it is available, and falls back to a curated headline otherwise. The next headline differs from the current headline whenever possible.
- Previous navigates back through the stored navigation stack and removes the last index if you go backward. It is disabled whenever the stack has fewer than two items or while loading.
- The headline takes its colour from the `--ink-display` token, so it is one consistent ink in each theme (12.3:1 on light, 13.1:1 on dark). It was previously assigned a random palette colour per shuffle and contrast-checked against a hardcoded background constant, which never evaluated dark mode. The update includes a short animation delay (60ms) to show the loader before revealing text.

### Accessibility
- `h3#headline` is programmatically focusable (`tabindex="-1"`) so it can be moved to after an update without entering the tab order.
- Loader uses `role="status"` with `aria-live="polite"`.
- Buttons retain visible focus outlines via CSS `:focus-visible` styling.

## Command rail (right column on wide screens)
The rail acts on the current wire item, not on the issue.

### Clipboard copy card
- `#copy-card`, labelled “Copy”. Its control is `#copy-btn` (“Copy item”),
  which prefers the Clipboard API and falls back to a hidden `<textarea>` plus
  `document.execCommand('copy')`.
- `#copy-status` reports success or failure (“No headline available to copy.”,
  “Copy failed. Please try again.”, “Clipboard unavailable in this browser.”).
  Errors add `.error`.

### Social share card
- `#share-card`, headed **“Share”**. `#native-share` (“Share from device”)
  opens the device share sheet where one exists.
- Links for Twitter, Facebook and Reddit update on every item change. The URL
  they carry holds one parameter, `headline`; the retired filter parameters are
  never written.
- Links open in a new tab with `rel="noopener noreferrer"` and an `aria-label`
  naming the destination.

### Clipping export card
- `#export-card`, headed **“Clipping”**. The sheet (`#clipping-front`) contains
  a masthead, `#clipping-date`, the kicker “Bulletin”, a rule, the item
  (`#clipping-headline`), the deck “Nobody has checked this.” and a footer
  reading “neckass.com · department of neckassery”.
- Two actions:
  - **Download clipping** (`#download-clipping`) renders the sheet to PNG via
    `html-to-image` and downloads it.
  - **Copy clipping** (`#copy-clipping`) renders to a blob and attempts
    `navigator.clipboard.write()`. Where image copy is unavailable it falls
    back to a download and reports “Clipboard unavailable. Downloaded front
    page.”
- `#export-status` reports progress and outcome; `#global-toast` gives compact
  confirmation for copy, share and export.

## The issue (front page)
- **Lead** — `#lead-headline`, `#lead-deck`, `#lead-byline`.
- **Briefs** — `#briefs-list`, seven items dealt from `data.HEADLINES`, minus
  anything already running as the lead.
- **Corrections** — `#corrections-list`. The first entry retracts a detail of
  the *previous* issue's actual lead, taken from that lead's `correction`
  field; the rest are dealt from `data.CORRECTIONS`. Issue 1 has nothing to
  correct and runs three general corrections.
- **Weather** — `#weather-line`, one entry.
- **Classifieds** — `#classifieds-list`, five entries.
- **Letters** — `#letters-list`, two entries, each a body and a signature.
- **Colophon** — the staff line and the paper's note.
- Pool depth is load-bearing: each pool must stay several times its deal size
  or a reader returning on consecutive days sees the same paper. Current
  shortest cycle is twelve days (classifieds).

## Back issues (`archive.html`)
- Lists recent issues newest first, each linking to `/?issue=YYYY-MM-DD`.
- The list is derived from the calendar, not stored, and stops at issue 1.
- Without JavaScript the page still explains the archive and links to today.

## Edge functions (Cloudflare Pages)
- `functions/feed.xml.js` serves `/feed.xml`: RSS for the last 30 issues,
  composed per request, `cache-control: public, max-age=3600`. Item titles and
  descriptions are XML-escaped.
- `functions/_middleware.js` rewrites `<title>` and the `og:`/`twitter:`
  title and description on the front page only, to the active issue's lead, so
  a shared link previews with the headline actually running. `og:image` is left
  static.
- Both compose the lead through `functions/lib/issue.mjs`, which mirrors the
  arithmetic in `modules/issue.js`. The leads are extracted to
  `functions/lib/leads.mjs` by `bun run feed:build`; `bun run feed:check` fails
  on drift and a smoke test asserts both runtimes select the same lead.

## Tiny LLM headline generator (`llm.js`)
- `llm.js` exposes a global `tinyLlmClient.generateHeadline()` that returns a promise with:
  - A randomized headline template that draws from subject/verb/object/impact pools and avoids recently generated duplicates.
  - A simulated latency delay between 420–880ms and a hard timeout at 2400ms. If the generation promise loses the race to timeout, it throws an error and `script.js` falls back to curated headlines.
  - A recent headline cache stored in localStorage (`tinyLlmRecentHeadlines`).

## Headline generation v2 specification (proposed)

This section defines a **v2 generation model** that keeps the app fully static/no-build while improving output quality, predictability, and accessibility-safe behavior. The v2 contract is additive: it can run alongside the current generator until rollout is complete.

### Product goals
- Generate headlines that feel more intentional and less repetitive while preserving the register.
- Keep generation resilient in constrained environments (local file, no network, older browsers).
- Keep Shuffle's output varied across a session rather than circling a handful of lines.
- Make generator outcomes inspectable for debugging and future tuning without shipping analytics dependencies.

### Non-goals
- No server calls or external LLM dependency.
- No new build tooling, bundlers, or transpilation requirements.
- No breaking changes to existing keyboard controls, copy/share/export flows, or URL semantics.

### Optional modern-web enhancements (progressive)
- v2 **may** use modern browser capabilities as progressive enhancements, with graceful fallback to the current baseline behavior.
- Recommended candidates:
  - `crypto.getRandomValues()` for stronger randomization than `Math.random()` when available.
  - `Intl.Segmenter` for better tokenization in query/relevance scoring.
  - `requestIdleCallback` for low-priority cache cleanup/diagnostic pruning.
  - `AbortController` to cancel stale in-flight generation requests when users rapidly shuffle.
  - Web Worker offload for candidate scoring if profiling shows main-thread jank.
- Compatibility contract:
  - Never require these APIs for core headline generation.
  - Feature-detect every API and fall back to lightweight synchronous logic.
  - Preserve direct `file://` compatibility and no-build/static hosting.

### v2 generator interface
- Expose `tinyLlmClientV2.generateHeadline(options)` as an async function.
- `options` shape:
  - `section?: string` — preferred section (for example: Local, Politics, Sports).
  - `source?: "curated" | "generated" | "any"` — generation preference.
  - `query?: string` — optional free-text constraint used as a soft relevance hint.
  - `exclude?: string[]` — headlines to avoid (typically recent stack entries).
  - `seed?: number` — optional deterministic seed for reproducible outputs.
- Return shape:
  - `headline: string`
  - `section: string`
  - `confidence: number` (0–1 heuristic score)
  - `reasonCodes: string[]` (debuggable labels like `"query-match"`, `"novel-structure"`)
  - `generatedAt: string` (ISO timestamp)

### Generation pipeline
1. **Context assembly**
   - Build a compact context object from the recently shown headlines, so the generator can avoid repeating them.
   - Normalize text (trim, collapse whitespace, lowercase for matching only).
2. **Candidate synthesis**
   - Assemble 12–24 candidates by combining template slots and phrase pools.
   - Use weighted pools by section so output reflects selected context before ranking.
3. **Scoring and ranking**
   - Score each candidate with a weighted heuristic:
     - Relevance to `query` tokens.
     - Novelty against recent generated/cache history.
     - Structural diversity (length/pattern variance).
     - Readability guardrail (avoid awkward punctuation clusters).
   - Select the highest-scoring candidate above a minimum threshold.
4. **Fallback handling**
   - If no candidate meets threshold, lower threshold once and retry ranking.
   - If still unavailable, throw a typed error consumed by existing curated fallback logic.

### Quality guardrails
- **Length target:** 45–110 characters, hard cap at 140.
- **Duplicate suppression:** no exact match with the last 30 generated headlines.
- **Near-duplicate suppression:** reject candidates with very high token overlap against last 10 shown headlines.
- **Safety/tone:** avoid direct harassment terms and preserve the wire-service voice rather than personal attacks.
- **Formatting:** sentence case headline text, no trailing punctuation unless stylistically required.

### State and persistence
- New localStorage key: `tinyLlmV2Recent` containing up to 60 entries with timestamps.
- Maintain backward compatibility with `tinyLlmRecentHeadlines`; on first load, migrate legacy entries into the new structure.
- Persist lightweight diagnostics only in memory for current session (no network reporting).

### Performance and resilience requirements
- Simulated generation latency: 280–720ms (faster than v1) with jitter.
- Hard timeout: 1800ms.
- On timeout or exception, return control to existing curated shuffle path with no blocking UI state.
- Generator must remain safe when localStorage is unavailable (private mode or quota errors).

### Accessibility and UX requirements
- Existing loader/status live regions remain the source of truth for announcing generation progress.
- Error messages must reuse established tone (brief, plain-language, action-oriented).
- Shuffle interaction must always conclude with either:
  - a newly rendered headline, or
  - a clear fallback outcome with controls restored.

### Integration plan
- Phase 1: ship `tinyLlmClientV2` behind a constant feature flag in `script.js` (default off).
- Phase 2: dual-run scoring in development mode to compare v1 vs v2 outputs without user-visible changes.
- Phase 3: enable v2 by default and retain v1 as emergency fallback path for one release window.
- Phase 4: remove v1-only code after stability checklist passes.

### Acceptance criteria
- 20 consecutive Shuffles produce at least 16 unique headlines.
- Timeout/error paths never leave loader visible or controls disabled after completion.
- Previous navigation continues to function across mixed curated+generated sessions.

### Validation checklist for implementation
- Add unit-style deterministic checks for seed-based reproducibility of candidate ranking.
- Add regression checks for duplicate suppression window behavior.
- Verify local file (`file://`) and `python -m http.server` workflows both function.
- Manually validate keyboard navigation, copy/share/export actions after v2 integration.

## Persistence & URL state
- LocalStorage keys:
  - `navigationStack`, `uniqueHeadlines`, `generatedHeadlines`, `favoriteHeadlines`, `headlineFeedbackLog` (current keys), plus legacy keys `headlinesViewed`, `viewedHeadlines`, `viewedStack` for backward compatibility.
- `navigationStack` is sanitized against current headline count; `uniqueHeadlines` falls back to the sanitized stack when missing.
- One URL query parameter carries state: `headline`, the current item's slug. Each headline render pushes or replaces history state so direct links and back/forward navigation both restore the item. The retired filter parameters (`section`, `q`, `source`, `panel`, `layout`) are stripped from any URL the app writes, so old links resolve to their headline and shed the rest.

## Keyboard interactions
- Arrow Right / Arrow Down trigger **Shuffle**.
- Arrow Left / Arrow Up trigger **Previous**.
- Key navigation is disabled when focus is inside editable elements (inputs, textareas, buttons, etc.).

## Error and edge cases
- If the headline list is empty, the headline shows “No items on file.” The Shuffle button is disabled and the loader is hidden.
- Metadata and social links are reverted to the base metadata and canonical URL (headline parameter removed) when there is no valid headline index.
- Headline contrast is guaranteed by the theme tokens rather than computed at runtime; `selectReadableColor()` and its colour helpers were removed once the token took over.

## Responsive behavior checkpoints
- **≥900px width**: two-column grid with sticky command rail at 24px from top.
- **541–899px width**: one-column stack with reduced hero margin.
- **≤600px width**: tighter body padding, stacked action buttons, visible quick-jump controls, full-width copy button, and reduced headline text size.

## Accessibility checklist
- All visible buttons and links have discernible text or `aria-label`s.
- Loader and status text areas use `aria-live="polite"` to announce updates.
- Visible focus outlines are preserved for keyboard navigation (`button:focus-visible`).
